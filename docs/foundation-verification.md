# سجل تحقق أساس الدخول والجلسات

التاريخ: 3 تشرين الثاني 2026. البيئة: معاينة تطوير خاصة؛ PostgreSQL حقيقي، pnpm monorepo، Node 24. لم يحدث نشر عام.

## ما تغيّر

أُنشئ أساس الدخول بكلمة مرور وتجزئة Argon2id، ثم طلب المستخدم صراحةً أن تبقى حسابات العرض بلا كلمة مرور للتجربة. التنفيذ النهائي يتيح اختيارها مباشرةً مع `DEMO_MODE=true`، ويبقي المسار المحمي اختيارًا منفصلًا. الجلسات محفوظة ومبطلة عند الخروج، والحسابات قابلة للتعطيل، مع تحديد محاولات وفحص مصدر وصلاحيات وصيغة خطأ عربية ثابتة، وإزالة الهواتف وتقليل البيانات، وترحيلات وإعداد منفصل يحافظ على العلاقات، وقاعدة اختبارات وساعة داخلية قابلة للحقن.

## أدلة التنفيذ

- طُبّق `pnpm --filter @workspace/db run migrate --adopt-existing` بنجاح على قاعدة التطوير بعد مطابقة المخطط الأولي. لا reset لبيانات العرض ولا إعادة إدخال لحساباته.
- `pnpm run typecheck` ناجح لجميع الحزم. عقد API أُعيد توليده.
- `pnpm test` النهائي بعد تعديل المستخدم: **25/25 ناجحة** في 13.93 ثانية، بقاعدة PostgreSQL مستقلة. تشمل الحسابات السبعة دون كلمات، ورفض الحساب المعطّل، وإيقاف الدخول والجلسات التجريبية خارج وضع العرض، وعدم إعادة تفعيل المعطّل أو إبطال جلسة قائمة عند تهيئة ما بعد الدمج المتكررة.
- اختبار استمرار الجلسة ليس إعادة استيراد وحدة فقط: يبدأ عملية خادم، يدخل، يوقف العملية، يبدأ عملية ثانية بنفس قاعدة الاختبار، يتحقق من الجلسة، يخرج، ثم يعيد إرسال الكوكي القديمة ويتحقق من بطلانها. يقارن الحسابات والطلبات قبل التشغيل وبعده أيضًا.
- الحارس يرفض اسم قاعدة العرض حتى مع اختلاف host/URL أو استعمال search_path، ويرفض قاعدة اختبار غير موسومة؛ التنظيف لا ينفذ قبل التحقق من هوية الاتصال الفعلية والوسم.

## حدود النتيجة

**لم تعد كلمات مرور العرض مطلوبة** بعد تعديل المستخدم. فُعّل وضع العرض في بيئة التطوير وشُغّل `accounts:setup:demo` بنجاح، دون أسرار كلمات مرور أو تغيير معرّفات الحسابات وروابط المركبات والطلبات. المسار الاختياري لكلمات المرور ما زال يرفض الإعداد الناقص دون قيم افتراضية؛ اختباره بكلمات عشوائية داخل قاعدة اختبار فقط.

أُعيد تشغيل مساري API والواجهة بنجاح بعد التغييرات، وسجلات التشغيل الحالية سليمة. فُحصت لقطة صفحة الدخول النهائية بعرض 360 بكسل: اسم «سرفيسنا» والشعار «على خطّك» وشارة العرض والحسابات السبعة ظاهرة، دون نموذج كلمة مرور أو تمرير أفقي ظاهر.

## نتيجة المتصفح التفاعلي

نجح فحص واحد بعرض 360×800:

- ظهرت الحسابات السبعة والشعار وشارة البيانات التجريبية، دون حقل كلمة مرور أو تمرير أفقي.
- اختيار الراكب فتح `/passenger`، وتحديث الصفحة حافظ على الجلسة.
- تسجيل الخروج أعاد شاشة الاختيار، وأكد `/api/auth/me` أن `authenticated:false`.
- اختيار السائق فتح `/driver` دون روابط هواتف أو أخطاء تشغيل ظاهرة، والخروج أبطل الجلسة.
- الوصول المباشر إلى `/admin` دون جلسة أعاد شاشة الاختيار.
- اختيار الإدارة فتح `/admin` وأظهر بيانات العمليات المحسوبة بدورها الصحيح؛ الخروج أبطل الجلسة، ولم تسجّل أخطاء واجهة أو console.

لم ينشئ فحص المتصفح طلبات ركوب أو يقبلها أو يلغها ولم يُعِد تهيئة العرض. استمرار الجلسة بعد إعادة تشغيل عملية الخادم وإبطال الكوكي المعادة مثبتان باختبار التكامل المعزول أيضًا، لمساري الدخول.

معايير A01–A24 الكاملة والاختبار الفعلي على Android وقياس خمس ثوانٍ أعمال لاحقة ولم تُقبل ضمن هذا السجل.
