# حالة استعادة ملفات سرفيسنا من Replit

آخر تحديث: 2026-11-15

## ما تم نقله إلى GitHub

1. وثيقة المواصفات المحفوظة من نسخة المسابقة بتاريخ 2026-11-03.
2. README يصف المشروع ويصرّح بأن السورس غير موجود بعد.
3. لقطة نصية موثّقة من الموقع المنشور.
4. إرشادات الاستعادة وملف `.gitignore`.

## ما لم يتم استعادته

هذه المجلدات والملفات غير متوافرة ضمن النسخة المرفوعة حتى الآن:

- كود واجهة التطبيق (المكونات والصفحات وملفات التنسيق الأصلية).
- كود الخادم وواجهات API والتحقق والصلاحيات.
- تعريف الجداول وملفات ترحيل قاعدة البيانات، والاختبارات.
- `package.json` وملف القفل وملفات الإعداد الأصلية.
- الصور والأيقونات والأصول الأصلية التي لا يمكن تنزيلها من ملف المشروع.
- نسخة احتياطية منفصلة ومحمية من بيانات المشروع التشغيلية (إن وُجدت).

## لماذا؟

أمكن العثور على مشروع Replit باسم «سرفيسنا» والتحقق من أن النشر ناجح، لكن الواجهة المتاحة للاتصال بمشروع Replit لم تُرجع محتويات الملفات. الموقع المنشور يعرض صفحة يمكن للزوار مشاهدتها، **وليس بالضرورة المصدر الذي وُلد منه التطبيق**. لذلك لم يتم الادعاء باستعادة مستودع الكود بالكامل، ولم ننشئ كودًا متخيَّلًا تحت أسماء ملفات المصدر الأصلية.

## إكمال الاستعادة بأمان

افتح المشروع الأصلي في Replit:
https://replit.com/@qut2006sib/srfysn

إذا بقي قسم **Files** متاحًا، صدّر المشروع بصيغة ZIP أو استخدم خيار Git/GitHub المتاح لرفع الملفات الأصلية. يمكن بعد ذلك استيراد السورس إلى هذا المستودع مع مراجعة الأسرار وملفات البيانات. لا ترفع محتوى `.env` أو كلمات المرور أو مفاتيح API أو أرقام هواتف ركاب حقيقيين إلى مستودع عام.

إذا كان الوصول إلى المحرر متوقفًا بعد انتهاء الاشتراك، يمكن التواصل مع دعم Replit بخصوص تصدير محتويات المشروع. **وجود رابط منشور لا يضمن إمكانية تنزيل المصدر الكامل أو قاعدة البيانات.**

## فحص الاستعادة بعد وصول السورس

1. التأكد من وجود ملفات المشروع ومطابقتها للنسخة المنشورة.
2. تثبيت التبعيات باستخدام ملف القفل الأصلي.
3. تشغيل الاختبارات وتدفقات الركوب الأساسية.
4. توثيق متغيرات البيئة المطلوبة دون قيمها السرية.
5. فصل بيانات العرض عن البيانات الحقيقية، وأخذ نسخ قواعد البيانات احتياطيًا بشكل خاص.
