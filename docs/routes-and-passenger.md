# الخط والمطابقة وشاشة الراكب

## ما تغير

- سجل مستقل لكل اتجاه، بهندسة مختلفة وست نقاط مرتبة من «نقطة تجريبية 1» إلى «نقطة تجريبية 6». لا يُعكس ترتيب قائمة مشتركة للعودة.
- نقاط مرتبطة بالاتجاه؛ تفعيل للاتجاه والنقطة والمركبة. لوحات `DEMO-001` إلى `DEMO-003`، وصف تجريبي، وسعة 6. الحسابات السبعة تبقى من إعداد الحسابات السابق.
- المخطط المحلي SVG يرسم الاتجاهين ونقاطهما والمركبات دون خرائط أو بلاطات خارجية؛ تظهر عبارة «المسار والنقاط تجريبية وغير معتمدة للملاحة».
- المطابقة تجرب جميع أزواج الصعود والنزول الصحيحة داخل الاتجاه. لكل طرف حد 600 متر قابل للتعديل باسم `MATCH_MAX_DISTANCE_METERS`. المقارنة قبل تقريب المسافة؛ سماحية حساب عشري أقل من نانومتر عند الحد الشامل.
- أفضل ثلاثة أزواج عالميًا بمجموع المسافتين، ثم معرّف ثابت مركب من اتجاه/صعود/نزول عند التعادل. اليدوي يرسل معرفي النقطتين دون إحداثيات ويفحص ترتيبهما؛ مسافاته `null` بدل الادعاء بقياس موقع الهاتف.
- النصان «الوجهة خارج نطاق الخط التجريبي» و«الخط مناسب، ولا يوجد سرفيس متاح الآن» يميزان صلاحية الخط عن وجود رحلة.
- شاشة «من وين، ولوين؟» بثلاث طرق للموقع، واختبار وجهة خارج الخط. إذن الموقع عند الضغط فقط؛ رفضه/انتهاء مهلته لا يمنع اليدوي. تغيير المدخلات يلغي الاقتراح والتحديد السابقين، وتُهمل الاستجابات المتأخرة.
- اختيار اقتراح ثم تأكيد نقطة الالتقاء قبل «اطلب سرفيس». لا اختيار تلقائي ولا تخصيص مركبة قبل قبول الخادم؛ المركبات «متاحة مبدئيًا». مسافات مباشرة تقريبية دون وقت وصول رقمي.
- سجل الراكب بصفحات: `GET /api/passenger/history?page=1&pageSize=10`، حجم أقصى 50، واستجابة `{items,page,pageSize,total,totalPages}`؛ الترتيب بالتاريخ ثم ID تنازليًا.

## الترحيل المحفوظ للقاعدة الموجودة

`lib/db/drizzle/0005_direction_routes.sql` يُطبّق داخل معاملة Drizzle ويقفل الجداول المتأثرة:

1. يؤرشف النقاط الأصلية (`enabled=false`) مع حفظ أسمائها وإحداثياتها ومعرفاتها الأصلية قدر الإمكان.
2. ينسخ النقاط التاريخية للاتجاه الآخر، ثم يحدّث روابط الطلبات والرحلات بالنسخة ذات الاتجاه الصحيح، **بنفس الاسم والإحداثيات**. لا يحذف طلبًا أو حدثًا، ولا يستبدل نقاطه التاريخية بنقاط العرض الجديدة.
3. يسجّل حدثًا نظاميًا لكل طلب `pending` أو `accepted` على التعريف السابق، ويلغيه بسبب `route_reconfigured` ويحرر المقعد إن كان مقبولًا. لا يُلغى طلب صاعد ولا يُفترض نزوله تلقائيًا؛ يبقى هو ورحلته حتى إتمامه الصريح.
4. ينهي الرحلات القديمة غير المرتبطة بطلب صاعد، وينشئ ست نقاط فعالة لكل اتجاه وهندسته الجديدة، ويحدث بيانات مركبات العرض دون تغيير IDs أو روابط الحسابات.

لا يُشغّل الترحيل أو seed أو reset عند بدء API. الترحيلات تطبق صراحةً أو من `scripts/post-merge.sh`؛ ملفات الترحيلات المطبقة محمية من التعديل ببصمة محتواها.

## إجراءات الإعداد الثلاثة

مع `DEMO_MODE=true`:

| الإجراء | النتيجة |
|---|---|
| `pnpm --filter @workspace/api-server run accounts:setup:demo` | الحسابات السبعة فقط؛ يحافظ على IDs والروابط. لا يحتاج كلمات مرور وفق تعديل المستخدم |
| `pnpm --filter @workspace/api-server run demo:base` | إنشاء تعريف الخط والمركبات إن لم يوجد خط؛ بلا رحلات أو طلبات |
| `pnpm --filter @workspace/api-server run demo:prepare` | سيناريو صريح: رحلتان محاكاة من بداية الاتجاهين وطلب للراكب الثالث؛ يرفض أي بيانات ديناميكية موجودة |
| `pnpm --filter @workspace/api-server run demo:reset` | **حذف ديناميكي مقصود** للطلبات والأحداث والرحلات وإبقاء الحسابات والجلسات وتعريف الخط؛ لا يعيد السيناريو |

إعداد التعريفات مساعدة مستقلة لا تعني إجراءً رابعًا للمستخدم: فصل **إعداد الحسابات، تحضير السيناريو، وإعادة تهيئته** واضح في الأوامر والواجهة. الإدارة تستعمل `/api/admin/prepare` و`/api/admin/reset`، محميين بالدور ووضع العرض. الإفراغ يتطلب تأكيدًا في الواجهة، ويرفض وجود بيانات مملوكة لحسابات خارج مجموعة العرض أو خط غير تجريبي.

لمسار الحسابات الاختياري بكلمة مرور: `accounts:setup` يقرأ الأسرار دون قيم افتراضية كما في دليل الحسابات؛ لم تُعد فرضه على العرض بلا كلمات مرور.

كشف فحص المتصفح ازدحام رأس الصفحة الذي سبّب تمريرًا أفقيًا. عُدّل الرأس ليفصل التنقل في سطر على الهواتف ويبقي الخروج ظاهرًا؛ نجح فحص أنواع الواجهة بعد الإصلاح. لم تُعد تجربة المسار بالكامل بعد تعديل التنسيق؛ قياس العرض النهائي وتجربة Android الفعلية يظلان ضمن تقرير القبول، ولا يُسجل A21 ناجحًا بالكامل هنا.

قاعدة الاختبارات مستقلة فعليًا وموسومة. لا ينفّذ حارس الاختبار تنظيفًا على قاعدة العرض، ولا يُقبل العزل بمخطط داخل قاعدة العرض. مخطط الترحيل المؤقت موجود **داخل قاعدة الاختبار المستقلة فقط** ويرجع بالكامل بعد الاختبار.

## ما بقي خارج هذه المرحلة

- السعة الذرية، المهل الجديدة، heartbeat، مفاتيح المحاولات وكامل الاعتمادية ضمن مرحلة الرحلات والسعة والاعتمادية.
- تنبيه الاقتراب وتأكيد الراكب «إي، ركبت» ضمن العمل المستقل المعتمد؛ لم يُعد هذا العمل إدخال رمز ركوب أو نقل ملكية التأكيد للسائق.
- Playwright متعدد الأدوار A01–A24، تجربة Android الفعلية وقياس زمن التحديث والتوثيق النهائي ضمن اختبارات القبول؛ نتائج المرحلة هنا ليست تقرير قبول كاملًا.
- لا Leaflet أو خرائط خارجية، ولا نشر عام أو تغيير لهوية المشروع أو لبنية pnpm.
