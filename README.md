# سرفيسنا — على خطّك

نموذج مسابقة عربي ببيانات تجريبية على خط الوعر ↔ وسط حمص. المشروع للمراجعة في المعاينة الخاصة، وليس لإطلاق عام أو تشغيل ركاب فعليين.

## الإعداد

1. العرض التجريبي **بلا كلمات مرور** حسب طلب المستخدم: اضبط `DEMO_MODE=true`. يلزم اتصال القاعدة و`SESSION_SECRET`، وليس أسرار كلمات حسابات العرض.
2. طبّق الترحيلات: `pnpm --filter @workspace/db run migrate`. للقاعدة القديمة التي سبقت سجل الترحيلات، استعمل `migrate --adopt-existing` مرة واحدة؛ سيُفحص التطابق قبل الاعتماد.
3. شغّل `pnpm --filter @workspace/api-server run accounts:setup:demo` لإعداد الحسابات السبعة، ثم اختر حسابًا من شاشة الدخول مباشرة. يحافظ على معرّفاتها وروابطها ولا يمسح الرحلات أو الطلبات.
4. لبيانات البداية الخالية من النشاط شغّل `pnpm --filter @workspace/api-server run demo:base`. تنشأ المركبات الثلاث بسعة 6 والاتجاهات بنقاطها، **بلا رحلات أو طلبات**.
5. شغّل معاينة API والواجهة عبر مساري العمل الموجودين. تشغيل الخادم لا يعيد تهيئة البيانات.

للمسار الاختياري المحمي بكلمة مرور بدل العرض: أضف الأسرار المسماة في `.env.example` عبر Secrets، شغّل `accounts:setup` ثم عطّل `DEMO_MODE`. لا كلمات افتراضية. وضع العرض يتيح اختيار جميع أدوار البيانات التجريبية لمن يستطيع الوصول للمعاينة؛ ليس إعدادًا لحسابات فعلية أو نشر عام.

## التحقق

```sh
pnpm run typecheck
pnpm test
```

الاختبارات ترفض قاعدة العرض وتستعمل PostgreSQL مستقلة موسومة للاختبار. التفاصيل والقرارات في [دليل الحسابات والجلسات](docs/accounts-and-sessions.md)، والنتائج والحدود في [سجل التحقق](docs/foundation-verification.md).

## تنبيه

ثلاثة إجراءات منفصلة: إعداد الحسابات بالأمر أعلاه؛ `demo:prepare` لتحضير سيناريو صريح (رحلتان وطلب) بشرط خلو البيانات الديناميكية؛ و`demo:reset` **لحذف الرحلات والطلبات والأحداث التجريبية والعودة لحالة خالية**. لا يمس الأخير الحسابات أو الجلسات أو تعريف الخط، وليس جزءًا من تشغيل الخادم. أزرار التحضير والإفراغ في الإدارة محمية بالدور و`DEMO_MODE`.

الاتجاهان مستقلان، بست نقاط لكل منهما. المسار والنقاط تجريبية وغير معتمدة للملاحة. المطابقة بالإحداثيات تستخدم حدًا لكل طرف مقداره 600 متر، قابلًا للتغيير عبر `MATCH_MAX_DISTANCE_METERS`. المسافات مباشرة تقريبية وليست توصيات مشي. الاختيار اليدوي لا يحتاج GPS. تفاصيل الترحيل والاختبارات في [توثيق الخط والراكب](docs/routes-and-passenger.md).

المواصفات الأصلية وتعديلات التنفيذ محفوظة في `docs/`. تعريف بنية pnpm وTailwind واختلافها عن المقترح موثق في `replit.md`. قواعد السعة والرحلات والمهل والحضور وإعادة المحاولات، مع أوامر الاختبارات وحدود التحقق، في [توثيق الرحلات والاعتمادية](docs/trips-and-reliability.md). تأكيد الصعود من الراكب فقط دون رمز أو شرط قرب؛ تنبيه الاقتراب وتقرير القبول الكامل وفحص المتصفح والأجهزة أعمال مستقلة.
